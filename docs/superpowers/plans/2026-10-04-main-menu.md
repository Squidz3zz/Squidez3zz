# Main Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a player joins, show a main menu with a title, Play/Settings/Credits buttons that pop on hover, and the player's own avatar idling on the right over a blurred orbiting view of the map. The player spawns only when they press Play.

**Architecture:**
- **UI:** the menu UI lives in `ReplicatedStorage.MainMenu` and a LocalScript clones it into PlayerGui. It can't live in StarterGui because `CharacterAutoLoads` is off.
- **Server:** a Script builds each player's avatar model and spawns them on a `PlayPressed` RemoteEvent. It also handles respawning after death.
- **Client modules:** button effects, the character preview, the menu camera and the volume slider are small ModuleScripts under the client LocalScript.

**Tech Stack:** Roblox Studio (Place1), Luau, the Roblox Studio MCP tools (`execute_luau`, `start_stop_play`, `get_console_output`, `screen_capture`, `user_mouse_input`), git.

**Spec:** `docs/superpowers/specs/2026-10-04-main-menu-design.md`

## Global Constraints

- **Scripts:** disk is the source of truth. Each Studio script has a file under `src/` with Rojo-style naming:

  | File on disk | Studio instance |
  |---|---|
  | `src/ServerScriptService/MenuServer.server.luau` | `ServerScriptService.MenuServer` (Script) |
  | `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/init.client.luau` | `StarterPlayer.StarterPlayerScripts.MainMenuClient` (LocalScript) |
  | `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/<Name>.luau` | ModuleScript `<Name>` under MainMenuClient |

- **Syncing scripts to Studio:**
  - **Pushing a file:** run `execute_luau` in the Edit datamodel. It finds or creates the instance (correct class, correct parent) and sets `.Source` to the file contents, embedded as a `[==[ ... ]==]` long string.
  - **Before editing a file:** read the Studio copy with `script_read`. If it differs from disk (the user edited it in Studio), copy Studio's version to disk first.
- **UI:** after Task 1 builds it, Studio is the UI's source of truth so the user can restyle it freely. `studio/build_main_menu_ui.luau` refuses to run if `ReplicatedStorage.MainMenu` already exists.
- **Tests:** these are `.luau` snippets in `tests/`. Run them with `execute_luau` in the named datamodel. Each one uses `assert(cond, "message")` and ends with `return "PASS"`. A test passes when the output is `PASS` and fails on any assert message or error.
- **Playtests:** use `start_stop_play`. Always stop the playtest before running Edit-datamodel code.
- **Studio instance id:** `f91ae60d-16e4-426a-8540-01e458e8eff0`. The place is named "Place1".
- **No hard-coded pixels:** all UI sizes and positions use Scale (Offset 0), except UIStroke thickness and UICorner radius.
- **Commits:** the message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Play pressed before the avatar finishes loading:** the menu must still close and the player must spawn. CharacterPreview must not error if the viewport is destroyed mid-load. Test: Task 5, Step 1, case B.
2. **Exploiter or double-click firing `PlayPressed` repeatedly, including after death:** the player is spawned exactly once by Play. Later fires do nothing and can't be used as an instant respawn. Test: Task 2, Step 1, case C.
3. **Avatar fetch fails, or a Studio test player has a negative UserId:** a default avatar is shown, not an empty frame or an error. Test: Task 2, Step 1, case A, which runs as a Studio test player.
4. **Player leaves before pressing Play:** their `MenuAvatars` entry is removed and nothing errors. Test: Task 2, Step 1, case D.
5. **Phone-sized screen:** the title, buttons and character don't overlap and the buttons stay tappable. Test: Task 7, Step 2.

### Task 2: MenuServer (avatar build, spawn on Play, respawn)

**Files:**
- Create: `src/ServerScriptService/MenuServer.server.luau`
- Test: `tests/menu_server.server.luau` (Server datamodel) and `tests/fire_play.client.luau` (Client datamodel)

**Interfaces:**
- **Produces:**
  - `ReplicatedStorage.PlayPressed` (RemoteEvent, created by the script if it's missing);
  - `ReplicatedStorage.MenuAvatars` (Folder);
  - `MenuAvatars[tostring(player.UserId)]` (Model with a Humanoid and HumanoidRootPart, and an `Animate` child if the rig has one).
- **Edit-time change:** set `Players.CharacterAutoLoads = false` in Edit and save it with the place. The script also sets it at runtime.

- [ ] **Step 1: Write the failing tests.**
  - `tests/menu_server.server.luau` covers four cases:
    - **(A) Avatar built:** after waiting up to 10s, `MenuAvatars[UserId]` exists and has a Humanoid. `player.Character == nil`.
    - **(B) After `fire_play` has run:** `player.Character ~= nil` and `MenuAvatars[UserId] == nil`.
    - **(C) Death and repeat fires:** record `local c = player.Character`, set `c.Humanoid.Health = 0`, and wait `Players.RespawnTime + 2`. Then `player.Character ~= c` (respawned). Record `local c2 = player.Character`, have the client fire PlayPressed 3 more times, wait 1s, and check `player.Character == c2` (no extra spawns).
    - **(D) Player leaves:** call the module-level cleanup on a fake entry. Put a Model named `"999"` in MenuAvatars, call the PlayerRemoving handler logic through a `_G.MenuServerTest_cleanup(999)` hook that only exists when `RunService:IsStudio()`, and check that the entry is gone.
  - `tests/fire_play.client.luau` fires `PlayPressed` N times (N is set at the top of the file).

- [ ] **Step 2: Start a playtest and run case A.** Expected: it fails, with no `MenuAvatars`.

- [ ] **Step 3: Implement `MenuServer.server.luau`.**
  - Set `Players.CharacterAutoLoads = false`. Handle players already in the game plus `PlayerAdded`.
  - **Avatar build:**
    - Get the description with `GetHumanoidDescriptionFromUserId` in a pcall, with one retry after 1s. On failure use `HumanoidDescription.new()`.
    - Get the rig type from `GetCharacterAppearanceInfoAsync(userId).playerAvatarType` in a pcall. It maps `"R6"` to R6; anything else, including failure, gives R15.
    - Build the model with `Players:CreateHumanoidModelFromDescription(desc, rigType)`, named `tostring(UserId)`, and parent it to MenuAvatars.
  - **On `PlayPressed`:** if `hasPlayed[player]`, return. Otherwise set the flag, destroy the avatar model and call `player:LoadCharacter()`.
  - **Respawn:** on `CharacterAdded`, connect `Humanoid.Died`. After `task.wait(Players.RespawnTime)`, if `player.Parent` is still set, call `LoadCharacter()`.
  - **PlayerRemoving:** destroy the avatar and clear the flag.
  - **Studio-only test hook:** `_G.MenuServerTest_cleanup`.
  - Then push the file to Studio and set `CharacterAutoLoads = false` in Edit (stop the playtest first).

- [ ] **Step 4: Playtest and run cases A → `fire_play` (N=1) → B → C → D.** Expected: `PASS` each time. Check `get_console_output` has no errors.

- [ ] **Step 5: Commit.**


### Task 4: ButtonEffects (hover pop)

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/ButtonEffects.luau`
- Modify: `init.client.luau` to call `ButtonEffects.attach` on Play, Settings, Credits and both Close buttons
- Test: `tests/button_effects.client.luau`

**Interfaces:**
- **Produces:**
  - `ButtonEffects.attach(button: GuiButton): ()`, which adds a `UIScale` named `PopScale` and a `UIStroke` named `PopStroke`;
  - `ButtonEffects.setState(button: GuiButton, state: "idle" | "hover" | "press"): ()`, the single place tweens happen. Events call it, and tests call it directly.
- **Exact values:**

  | State | PopScale.Scale | PopStroke.Transparency |
  |---|---|---|
  | idle | 1.0 | 1 |
  | hover | 1.1 | 0 |
  | press | 0.95 | 0 |

  - PopStroke is white with Thickness 2 and `ApplyStrokeMode = Border`.
  - Tweens use `TweenInfo.new(0.15, Enum.EasingStyle.Back, Enum.EasingDirection.Out)`.
- **Event wiring:**
  - `MouseEnter` and `SelectionGained` go to `hover`. `MouseLeave` and `SelectionLost` go to `idle`.
  - `MouseButton1Down` goes to `press`. `MouseButton1Up` goes to `hover` if the mouse is still over the button, otherwise `idle`.
  - On touch input (`UserInputType.Touch`), `InputBegan` goes to `hover` and `InputEnded` goes to `idle`.

  - Call `setState(play, "idle")`, wait 0.3s, and assert the scale is within 0.01 of 1.0.
  - The module is reached through `_G.MainMenuTest.ButtonEffects`.

### Task 5: CharacterPreview (avatar in viewport, idle + wave)

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/CharacterPreview.luau`
- Modify: `init.client.luau`. Wait for `MenuAvatars[UserId]` (timeout 15s) in a `task.spawn`, then call `CharacterPreview.show(CharacterView, avatar)` only if `MainMenu` still exists.
- Test: `tests/character_preview.client.luau`

**Interfaces:**
- **Consumes:** the Task 2 avatar model and the Task 1 `CharacterView` and `WorldModel`.
- **Produces:** `CharacterPreview.show(viewport: ViewportFrame, source: Model): Model?`. It returns the clone, or nil if `viewport` was destroyed.
- **Behaviour:**
  1. Clone `source`.
  2. Read the idle ID from `clone.Animate.idle.Animation1.AnimationId` if present, then **destroy `clone.Animate`**. It's a LocalScript and would run inside PlayerGui.
  3. Anchor `HumanoidRootPart`, pivot the clone to `CFrame.new()`, and parent it to `viewport.WorldModel`.
  4. Create a Camera named `PreviewCamera` with FieldOfView 30, parent it to the viewport and set `viewport.CurrentCamera`.
  5. Frame the camera: take the bounding box from `clone:GetBoundingBox()` and set the camera distance to `(height/2) / math.tan(math.rad(15)) * 1.15` along the root's `LookVector`, so the character faces the camera.
  6. Get the Animator from the Humanoid, creating one if it's missing.
  7. Play the idle on loop. If no ID was read, use the fallback: R15 `rbxassetid://507766666`, R6 `rbxassetid://180435571`.
  8. Play the wave once with `Looped=false`: R15 `rbxassetid://507770239`, R6 `rbxassetid://128777973`.
  9. Wrap each animation load in a pcall. A failure leaves the bind pose and doesn't throw.

- [ ] **Step 1: Write the failing test.**
  - **(A)** Wait up to 15s for a Model in `CharacterView.WorldModel`. Then assert:
    - it has a Humanoid and no `Animate` descendant;
    - `CharacterView.CurrentCamera.Name == "PreviewCamera"`;
    - one of the Animator's `GetPlayingAnimationTracks()` has `Looped == true`.
  - **(B)** In a fresh playtest, call `_G.MainMenuTest.play()` immediately, before the avatar arrives. Wait 15s and assert there were no errors, using a `LogService.MessageOut` listener installed at the start of the test that counts `MessageError` entries, and that `player.Character ~= nil`.

- [ ] **Step 2: Playtest, run case A, and verify it fails.** Expected: `no model in WorldModel`.

- [ ] **Step 3: Implement `CharacterPreview.luau` and the call in `init.client.luau`.** Push both files.

- [ ] **Step 4: Playtest and run case A.** Expected: `PASS`. Take a `screen_capture` to confirm the character faces the camera and waves. Run case B in a new playtest. Expected: `PASS`.

### Task 6: MenuCamera (orbit + blur) and VolumeSlider

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/MenuCamera.luau`
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/VolumeSlider.luau`
- Modify: `init.client.luau`. Call `MenuCamera.start()` on open and `VolumeSlider.attach(SettingsPanel.Slider, SoundService.Music)`.
- Test: `tests/camera_slider.client.luau`

**Interfaces:**
- **MenuCamera:**
  - **`start(): ()`**
    - Sets `workspace.CurrentCamera.CameraType = Scriptable`.
    - Orbits the focus point at radius 60 and height 30, one revolution per 60s, looking at the focus. It's driven by `RunService.RenderStepped`.
    - The focus point is `workspace.MenuCameraFocus.Position` if a Part with that name exists, otherwise `Vector3.zero`.
    - Adds a `BlurEffect` named `MenuBlur` (Size 16) to Lighting.
  - **`stop(): ()`** disconnects the orbit, tweens `MenuBlur.Size` to 0 over 0.4s and then destroys it, and sets `CameraType = Custom`.
- **VolumeSlider:**
  - `VolumeSlider.attach(slider: Frame, group: SoundGroup): ()`.
  - Dragging (mouse or touch) on `slider` sets `group.Volume = math.clamp(alpha, 0, 1)`.
  - `slider.Fill.Size.X.Scale` and `slider.Knob.Position.X.Scale` follow `alpha`.
  - The initial alpha is `group.Volume`.
  - Also exposes `VolumeSlider.setAlpha(slider: Frame, group: SoundGroup, alpha: number): ()`, which events and tests share.

  - Call `setAlpha(slider, Music, 1.7)` and assert the volume is 1.
  - Call `play()`, wait for the menu to close, and assert `CameraType == Custom` and that `Lighting:FindFirstChild("MenuBlur") == nil`.
