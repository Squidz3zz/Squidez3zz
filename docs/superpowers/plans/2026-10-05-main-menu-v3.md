# Main Menu v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a factory-themed loading screen that preloads assets, per-scene background music and button sound effects tied to the Settings sliders, a foreground "YOU" viewer avatar in Credits, and a main-menu avatar that waves repeatedly.

**Architecture:**
- **Loading screen and asset config:** a `ReplicatedFirst` LocalScript shows the loading screen and preloads, using the `ReplicatedFirst.MenuAssets` config. It then hands over to `MainMenuClient` through the PlayerGui attribute `LoadingDone`.
- **Audio:** two new client modules. `MenuAudio` handles scene music, switching tracks through a new SceneDirector `onSceneChanged` callback. `ButtonSounds` handles SFX, hooked into `ButtonEffects` (a new `onHover` option) and the button `Activated` handlers.
- **Credits and avatar:** CreditsRoom places the viewer on a new `ViewerSpot` marker. CharacterPreview loops the wave.

**Tech Stack:** Roblox Studio, Luau, Roblox Studio MCP tools, git.

**Spec:** `docs/superpowers/specs/2026-10-05-main-menu-v3-design.md`. It builds on the v2 and v1 specs and the code on `master`.

## Global Constraints

### Studio and the place
- Call `list_roblox_studios` first, because the id changes on every restart. The place is "Untitled Experience" (placeId 95688118364991).
- **Never save or publish** the place.
- If RenderStepped stops firing or the viewport is 1x1, the screen is locked: stop and report BLOCKED.

### Scripts and the build baseline
- Disk is the source of truth. Use Rojo-style paths:
  - `src/ReplicatedFirst/<Name>.luau` → ModuleScript, or `<Name>.client.luau` → LocalScript, in ReplicatedFirst.
  - `src/ServerScriptService/MenuServer.server.luau`.
  - `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/init.client.luau`, with its sibling `.luau` files as ModuleScripts.
- To push a script, run an Edit find-or-create that sets `.Source` from a `[====[ ... ]====]` long string.
- After pushing, verify `#Source` equals the file length. The working tree is CRLF because `core.autocrlf` is true, so normalise to LF before comparing.
- Before editing a script, `script_read` the Studio copy. If it differs from disk (after LF normalisation), stop and report.
- **UI and room changes:** apply them live AND in the matching build script (`studio/build_main_menu_ui.luau` or `studio/build_menu_rooms.luau`). These scripts are the recovery baseline.

### Tests
- Tests are `.luau` snippets in `tests/`. Run each with `execute_luau` in the datamodel its suffix names. Each one uses `assert(cond, "message")` and ends with `return "PASS"`.
- `sway` always runs last, because it presses Play. `loading` must be the first call in its fresh playtest.
- Studio-only test hooks are `BindableFunction`s named `TestHook`, created only when `RunService:IsStudio()`. Never use `_G`.
- Tests `require` a separate module copy, so any state a test observes must live on Instances.

### Play path and fault isolation (v1/v2)
- Nothing new may yield on the Play path.
- `SceneDirector.stop()` and the new `MenuAudio.stop()` must not yield, and must be safe to call more than once.
- Every module call from init is pcall'd.
- Keep the I-1 fallback.
- Scene hooks and callbacks must not yield and must be safe to call more than once.

## Review Focus

1. **One of the six sounds fails to load** (the asset isn't public or isn't owned). Expect a single warning naming the key, every other sound still playing, and no errors. Test: Task 2 Step 1 case S-C.
2. **Scenes switched rapidly, or Play pressed mid-crossfade.** Expect only one track audible at a time, and no music Sound left after Play. Test: Task 3 Step 1 cases M-B and M-C.
3. **The loading screen script is missing or errors.** Expect the menu to still open after the timeout, the player still able to Play, and no loading gui left on screen. Test: Task 1 Step 1 case L-B.
4. **Hovering inside the same button, or re-selecting it.** Expect the hover sound once per idle→hover transition, not on every mouse move. Test: Task 2 Step 1 case S-A.
5. **The "YOU" avatar on a phone-shaped view.** Expect it not to cover the developer's head, the developer's name label, or BACK. Test: Task 4 Step 1 case Y-A.

**Files:**
- Create: `src/ReplicatedFirst/MenuAssets.luau`
- Create: `src/ReplicatedFirst/LoadingScreen.client.luau`

**Interfaces:**
- **Produces `MenuAssets`:**
  - `Sounds: { Hover: string, Confirm: string, PlaySelect: string, MenuMusic: string, SettingsMusic: string, CreditsMusic: string }`, with the values above.
  - `Tips: { string }`: 6–8 uppercase factory flavour lines, e.g. "TIP: THE FURNACE NEVER SLEEPS. NEITHER DO WE."
  - `LOADING_MIN_SECONDS = 2`, `LOADING_MAX_SECONDS = 20`, `TIP_SECONDS = 4`.
- **Produces, from LoadingScreen:**
  - PlayerGui attributes: `LoadingDone` (boolean), `LoadingFailedSounds` (a comma-separated string of keys, empty if none), `LoadingShownAt` and `LoadingDoneAt` (`os.clock()` numbers), and `LoadingTipChanges` (a number).
  - A ScreenGui `PlayerGui.LoadingScreen` with descendants named `Title`, `Spinner` and `Tip`.
  - A Studio-only `TestHook` under the script. `Invoke("state")` returns `{ done = bool, failed = string }`.
- **LoadingScreen behaviour:**
  1. Build the gui with IgnoreGuiInset true, ScreenInsets None, DisplayOrder 20 and ResetOnSpawn false.
  2. Parent it, then call `RemoveDefaultLoadingScreen()`.
  3. Preload in parallel, with an overall cap of `LOADING_MAX_SECONDS`:
     - `game.Loaded`;
     - `ContentProvider:PreloadAsync` over 6 temporary Sounds;
     - the 3 menu ScreenGuis;
     - both rooms;
     - `MenuAvatars[userId]`.
  4. Hand off once at least `LOADING_MIN_SECONDS` have passed: fade to black over 0.4 s, set `LoadingDone`, wait for `MenuOpen` (at most 3 s), fade out over 0.4 s, then destroy.
  - The spinner rotates continuously.
  - The tip cycles every `TIP_SECONDS`, and `LoadingTipChanges` is incremented on each change.
- **init:** `waitForLoading()` runs in `setupMenu` before parenting.
  - If `ReplicatedFirst:FindFirstChild("LoadingScreen")` is nil, it returns immediately.
  - Otherwise it waits on the attribute signal for up to `LOADING_MAX_SECONDS + 5`. On timeout it warns and continues.

### Task 2: Button sound effects

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/ButtonSounds.luau`

**Interfaces:**
- **Consumes:** `MenuAssets.Sounds` (Task 1), read with `require(ReplicatedFirst:WaitForChild("MenuAssets", 10))`. If it's missing, the module warns and makes every call a no-op.
- **Produces `ButtonSounds`:**
  - `init(): ()` creates three Sounds in SoundService, named `MenuSfxHover`, `MenuSfxConfirm` and `MenuSfxPlay`, each with `SoundGroup = SoundService.SFX`. It is idempotent.
  - `hover(): ()`, `confirm(): ()` and `playSelect(): ()` each set `TimePosition = 0` and call `Play`. They never yield, and skip if the sound isn't loaded after its load attempt.
  - The module finds the Sounds by name, so test copies work.
- **Produces `ButtonEffects.attach(button: GuiButton, opts: { onHover: (() -> ())? }?)`:**
  - `onHover` fires only on an idle→hover transition: MouseEnter, SelectionGained, or touch InputBegan while not already hovered. It is pcall'd.
  - Existing callers that pass no `opts` are unchanged.
- **init wiring:**
  - PLAY, SETTINGS, CREDITS and BACK attach with `onHover = ButtonSounds.hover`.
  - The Activated handlers call `pcall(ButtonSounds.confirm)` (SETTINGS, CREDITS, BACK) or `pcall(ButtonSounds.playSelect)` (PLAY) first.
  - `playSelect` is not stopped by the Play fade.
- **SettingsBoard:** each switch row plays hover on `MouseEnter` and confirm when flipped. It receives ButtonSounds through a new optional `SettingsBoard.mount(board, playerGui, sounds?)` argument.

### Task 3: Scene music

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/MenuAudio.luau`
- Modify: `SceneDirector.luau` (the optional `ctx.onSceneChanged`) and `init.client.luau` (start, scene callback, stop on Play)
- Test: `tests/audio.client.luau` (cases M-A, M-B, M-C)

**Interfaces:**
- **Consumes:** `MenuAssets.Sounds` (Task 1), and `SceneDirector.init(ctx)` (v2).
- **Produces `MenuAudio`:**
  - **`start(): ()`**
    - Creates `SoundService.MenuMusic`, `SettingsMusic` and `CreditsMusic`, each with `Looped = true`, `SoundGroup = SoundService.Music` and `Volume = 0`.
    - Fades `MenuMusic` to Volume 1 and plays it.
    - It is idempotent.
  - **`setScene(name: "Menu" | "Settings" | "Credits"): ()`**
    - Tweens the current track's Volume to 0 over 0.8 s, then pauses it.
    - Resumes the target track, or plays it from the start the first time, and tweens it to 1 over 0.8 s.
    - It never yields.
    - The track for each scene name is found by its Sound name, so test copies work.
  - **`stop(): ()`**
    - Never yields and is idempotent.
    - Tweens every music track to 0 over 0.4 s, then stops and destroys it.
- **SceneDirector:** if `ctx.onSceneChanged` is set, call it right after the current scene is switched, behind the fader, inside pcall, with no yield.
- **init:**
  - `pcall(MenuAudio.start)` when the menu opens.
  - Pass `MenuAudio.setScene` as `onSceneChanged`.
  - In `runPlay`, call `pcall(MenuAudio.stop)` right after `SceneDirector.stop`.
