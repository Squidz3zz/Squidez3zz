# Main Menu v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the v1 main menu a heavy-factory restyle (new layout, waist-up avatar, vignette, mouse sway) and turn Settings and Credits into fade-cut 3D factory rooms. Settings shows a board UI; Credits shows hoverable developer and viewer avatars.

**Architecture:**
- A new client `SceneDirector` owns three scenes (Menu, Settings, Credits). Each scene sets the camera base CFrame from a marker part, shows or hides UI, and runs that scene's enter/exit hooks behind the existing `Fader`.
- `MenuCamera` is rewritten from an orbit to base-CFrame-plus-mouse-sway.
- Two new client modules build the rooms' interactive parts: `SettingsBoard` (a SurfaceGui) and `CreditsRoom` (avatars plus hover).
- The rooms are Persistent Models under the map, built by a recovery build script.
- The server additionally builds the developer's credit avatar.

**Tech Stack:** Roblox Studio, Luau, Roblox Studio MCP tools (`execute_luau`, `start_stop_play`, `script_read`, `get_console_output`, `screen_capture`, `user_mouse_input`), git.

**Spec:** `docs/superpowers/specs/2026-10-04-main-menu-v2-design.md`. It builds on v1 (`docs/superpowers/specs/2026-10-04-main-menu-design.md`) and the v1 code on `master`.

## Global Constraints

- **Studio instance:** call `list_roblox_studios` first. The id changes on every Studio restart. Today it is `1ded526b-9cac-4dae-bca7-78585ce3e17e`, "Untitled Experience" (placeId 95688118364991).
- **Never save or publish** the place. The user does that.
- **Scripts:**
  - Disk is the source of truth. Use Rojo-style paths: `src/ServerScriptService/MenuServer.server.luau`, `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/init.client.luau`, and the ModuleScripts `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/<Name>.luau`.
  - To push a script, run `execute_luau` (Edit) that finds or creates the instance with the right class and parent, then sets `.Source` to the file contents inside a `[====[ ... ]====]` long string. Luau drops a newline that comes right after the opening bracket.
  - After pushing, verify that `#Source` equals the file's byte size. Files use LF line endings.
  - Before editing a script, `script_read` the Studio copy. If it differs from disk, stop and report.
- **UI and rooms:** Studio is the source of truth after a build. Every change must ALSO be made in the matching build script (`studio/build_main_menu_ui.luau` or `studio/build_menu_rooms.luau`), because these scripts are the disaster-recovery baseline.
- **Tests:**
  - Tests are `.luau` snippets in `tests/`, run with `execute_luau` in the datamodel their suffix names (`.edit`, `.server`, `.client`). Each uses `assert(cond, "message")` and ends with `return "PASS"`.
  - Poll with timeouts; never use long fixed sleeps.
  - Run any test that measures camera motion LAST in its playtest, because the harness resets CameraType after execute_luau calls.
- **Studio-only hooks:** test hooks are `BindableFunction`s named `TestHook`, created only when `RunService:IsStudio()`. Never use `_G`.
  - Tests reach modules by `require`-ing the ModuleScript. That gives the test a separate copy, so module state that tests observe must live on Instances (attributes, children), not in module locals.
- **Fault isolation (v1):**
  - Every module call from `init.client.luau` is pcall'd and warns on failure.
  - Nothing new may yield on the Play path.
  - The v1 I-1 fallback stays: if the menu can't be set up, warn, destroy it, and `PlayPressed:FireServer()`.
- **No hard-coded pixels in menu UI:** use Scale only (Offset 0). The exceptions are UIStroke thickness, UICorner radius and the SurfaceGui's PixelsPerStud.
- **Factory palette:**

  | Use | Value |
  |---|---|
  | Panel / button background | RGB(38,36,34) |
  | Accent / amber | RGB(255,150,30) |
  | Vignette | RGB(12,9,6) |
  | Lamp light | RGB(255,160,60) |
  | Font | Oswald (`Enum.Font.Oswald`; use `Font.fromEnum(Enum.Font.Oswald)` with `Enum.FontWeight.Bold` for bold) |
  | Labels | uppercase |

- **Transitions:** 0.4s fade to opaque, cut, then 0.4s fade back in.
- **Sway:** at most 2° yaw and 2° pitch, smoothing alpha `1 - math.exp(-6 * dt)`.
- **Commits:** end every commit message with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feature/main-menu-v2`.

### Task 2: MenuSettings and the sway camera

**Files:**
- Create: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/MenuSettings.luau`
- Rewrite: `src/StarterPlayer/StarterPlayerScripts/MainMenuClient/MenuCamera.luau`

**Interfaces:**
- **`MenuSettings`.** State lives in `LocalPlayer` attributes, so test copies share it.
  - `get(name: "CameraSway" | "ScreenEffects"): boolean` reads attribute `MenuSetting_<name>`. nil means `true`.
  - `set(name, value: boolean): ()`.
  - `changed(name): RBXScriptSignal` returns `LocalPlayer:GetAttributeChangedSignal("MenuSetting_" .. name)`.
  - This deliberately departs from the spec's "Changed BindableEvent". Attributes are needed because tests run a separate module copy.
- **`MenuCamera`:**
  - `start(): ()`:
    - Sets CameraType Scriptable and base = `menuBase()`.
    - If ScreenEffects is on, adds `Lighting.MenuBlur` (BlurEffect Size 6) and `Lighting.MenuColorCorrection` (ColorCorrectionEffect: Contrast 0.1, Saturation -0.15, TintColor RGB(255,235,210)).
    - Listens to `MenuSettings.changed("ScreenEffects")` to remove or re-add both.
    - Connects a RenderStepped sway updater.
  - `menuBase(): CFrame` returns the Workspace attribute `MenuCameraShot` (a CFrame) if set, else `CFrame.lookAt(Vector3.new(0, 40, 80), Vector3.zero)`.
  - `setBase(cf: CFrame): ()`:
    - Stores the base as attribute `MenuBaseCFrame` on `workspace.CurrentCamera`.
    - Snaps the camera to `cf`, since the cut happens behind the fader.
    - Resets the smoothed sway to zero.
  - `stop(): ()` keeps the v1 contract: non-yielding and idempotent. It disconnects everything, tweens MenuBlur Size to 0 over 0.4s and then destroys it, destroys MenuColorCorrection, and sets CameraType Custom.
- **Sway** (each frame):
  - `nx, ny` = mouse offset from the viewport centre ÷ half the viewport size, clamped to -1..1.
  - Target = `CFrame.Angles(-ny * math.rad(2), -nx * math.rad(2), 0)`, smoothed with alpha `1 - math.exp(-6 * dt)`.
  - Camera = base × smoothed rotation.
  - The target is identity when `MenuSettings.get("CameraSway")` is false, when `not UserInputService.MouseEnabled`, or when `UserInputService:GetLastInputType()` is Touch or a Gamepad type.
- **`MenuServer`:**
  - At startup, if `workspace.MenuCameraShot` is a BasePart, set Workspace attribute `MenuCameraShot` = its CFrame. The spec says "Vector3 position", but the camera needs the marker's orientation too, and attributes support CFrame.
  - Stream around that position, or `Vector3.zero` if there is no marker, in its own thread, exactly as v1 streams around the focus.
  - Remove `MenuCameraFocus` completely, including its comments.

### Task 4: SceneDirector and the scene transitions

**Files:**

**Interfaces:**
- **Consumes:**
  - `MenuCamera.setBase(cf)` and `MenuCamera.menuBase()` (Task 2);
  - Task 3's `Root`, `Back` and `Fader`;
  - the Task 1 markers `workspace.SettingsRoom.SettingsCameraShot` and `workspace.CreditsRoom.CreditsCameraShot`.
- **Produces:**
  - **`SceneDirector.init(ctx: { fader: Frame, root: GuiObject, back: GuiButton, menuCamera: table? }): ()`.** It wires `back.Activated` to `goTo("Menu")`.
  - **`SceneDirector.register(name: string, hooks: { enter: (() -> ())?, exit: (() -> ())?, dispose: (() -> ())? }): ()`.** Tasks 5 and 6 register their hooks under "Settings" and "Credits".
  - **`SceneDirector.goTo(name: "Menu" | "Settings" | "Credits"): boolean`.**
    - It returns false if a transition is running, if `name` is already the current scene, or if the target's marker is missing; a missing marker also warns.
    - Otherwise it starts the transition in its own thread and returns true. The transition:
      1. tweens Fader to 0 over 0.4s;
      2. runs `pcall(old.exit)`;
      3. sets the base: `menuCamera.setBase` with the marker CFrame, or with `menuBase()` for Menu;
      4. sets `root.Visible = (name == "Menu")` and `back.Visible = (name ~= "Menu")`;
      5. runs `pcall(new.enter)`;
      6. tweens Fader to 1 over 0.4s.
  - **`SceneDirector.stop(): ()`.** This is the Play path, so it must not yield. It cancels any running transition (a stopped flag that the transition thread checks between steps), runs `pcall(current.exit)`, and runs `pcall(hooks.dispose)` for every scene.
  - **Scene state:** the current scene name is mirrored to the `PlayerGui` attribute `MenuScene`. It starts as `"Menu"`.
- **`init.client.luau`:** in `runPlay`, before `fadeTo(0)`, call `pcall(SceneDirector.stop)`, followed by `root.Visible = true` and `menu.Back.Visible = false`. The menu is destroyed shortly after anyway.
